# C2.5J — Persistent Interaction Snapshot and Damage Narrowing

C2.5I made the 50,000-line fixture usable, but its accepted native trace still
showed two measurable costs:

- 238 interaction snapshots were rebuilt, averaging about 16.8 ms each;
- 223 of 240 frames used the full-scene path.

C2.5J attacks those measured costs without changing document ownership or Luna's
revision-stable presentation contract.

## Changes

- Pane geometry and the shared presentation bundle are cached across compatible
  host interactions.
- The cache key includes document identity/revision, framebuffer size, pane
  geometry generation, pane-view generation, and active pane identity.
- Pane surfaces are built lazily. Pointer work materializes only the pane it
  actually touches, and repeated compatible hover events reuse that target surface.
- Pointer movement that changes only the platform cursor requests no redraw.
- Selection, caret, scrollbar, and wheel interactions now request pane-visual
  damage instead of generic full-scene input damage.
- Backspace, Delete, and Enter are classified as document edits when they mutate
  the current buffer, allowing the existing partial document-damage path.
- Runtime schema 4 records interaction snapshot requests/builds/cache hits,
  lazy target-surface builds, no-render events, pane-visual events, document-edit
  events, and full-scene events.

## Safety and correctness boundaries

- Any document revision change invalidates snapshot compatibility.
- Any pane split or window geometry change advances the geometry generation.
- Any viewport, caret, or selection mutation advances the pane-view generation.
- Overlay/menu activity, pane resizing, new/open document operations, and other
  broad product mutations continue to use full-scene rendering.
- The accepted C2.5H Luna submodule pin remains unchanged.
- The C2.5I Moth icon, desktop launcher, and current-user installation path remain
  unchanged and are revalidated by the delivery.
