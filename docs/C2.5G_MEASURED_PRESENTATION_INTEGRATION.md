# C2.5G — Measured Moth Presentation Integration

This checkpoint applies the previously prepared bounded-damage and virtualized
presentation work to Moth's real application shell, then records what the shell
actually does.

## Paired dependency rule

Moth must pin one exact accepted Luna C2.5G commit. `scripts/update-luna-exact.sh`
refuses a moving branch, verifies the remote branch head, checks out the supplied
40-character SHA detached, stages the submodule gitlink, and proves all four SHAs
match.

## Real-shell attribution

Set both trace paths for a paired native run:

```bash
LUNA_RUNTIME_TRACE_PATH="$PWD/luna-runtime.json" \
MOTH_RUNTIME_TRACE_PATH="$PWD/moth-runtime.json" \
  swift run MothTextLinux
```

Moth records revision presentation requests/builds/hits, pane-surface builds,
minimap plans and samples, and full/partial/cached frame paths. Luna separately
records host polling, dispatch, render, present, sleep, and renderer capability
work. The two JSON files should be reviewed together.

## Scalability matrix

Run the generated native fixtures at 50, 500, 5,000, and 50,000 lines. For every
size, verify typing, arrows, page navigation, wheel/touchpad scrolling, scrollbar
paging and dragging, split resizing, overlay open/close, and resize recovery.

Acceptance requires:

- one revision projection shared by both panes and the minimap;
- viewport-bounded shaping with bounded retention;
- minimap sampling bounded by pixel height;
- document edits using partial damage after the cold full frame;
- overlays and resize conservatively using full-scene fallback;
- no sluggishness, hang, crash, OOM, or force quit;
- both JSON traces retained with the accepted commit SHAs.

Do not merge either paired branch or begin M3A until these native gates pass.
